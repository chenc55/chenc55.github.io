01 / AI 与数据 · 学习规划

岗位技能差距分析与学习规划系统

一项连接岗位数据分析与学习规划的 Web 应用实践，将技能要求、自评差距和学习任务组织成可解释的流程。

项目简介问题与思路操作演示界面与功能实现原理技术栈项目思考

01 / 项目简介

从岗位数据出发，连接分析结果与学习行动。

这个项目围绕准备就业时的三个问题展开：目标方向需要哪些技能，当前差距在哪里，有限时间里应该先学什么。招聘描述的叫法、城市和方向各不相同，需要先整理数据与比较范围，才能给出有依据的分析。

这段实践把岗位统计、个人自评和学习规划连接起来，重点在于数据处理与页面流程的衔接：让差距可以回到具体输入，让学习任务既有先后关系，也有时间预算。

应用场景

面向准备就业、需要对照目标岗位梳理技能与学习投入的学生。

实践内容

  • 岗位技能统计与可视化
  • 技能自评与差距解释
  • 前置关系与学习任务排期

02 / 问题与思路

从具体问题，梳理实现思路。

01

要求多，难以确定重点

遇到的问题
单个岗位的描述不能代表整个方向，直接混合不同资料容易产生误解。
实现思路
按方向、城市和资料类型固定分析范围，展示技能出现频率与有效样本数。
02

知道差距，却看不懂分数

遇到的问题
只有一个匹配分，无法解释某项技能为何需要优先补足。
实现思路
同时展示自评等级、目标等级、需求权重和差距，保留报告生成时的输入。
03

想学很多，时间却排不下

遇到的问题
学习清单忽略基础技能与可投入时间，容易把尚未具备前提的目标排在前面。
实现思路
补齐人工维护的前置关系，再按每周投入预览任务与周安排，提示时间缺口。

04 / 实现原理

一次操作，背后如何流转。

分数能回到具体输入

有效样本至少 100 条才进入评分；选取出现频率不低于 10% 的前 20 项技能。按需求次数赋权，将自评相对目标的完成比例加权汇总，得到固定样本内的自评覆盖度。

先满足前置，再考虑优先级

规划器把技能提升拆为逐级任务，检查前置关系是否成环。只有前提已满足的任务才参与优先排序，再用整数分钟核算每周容量，避免把学习顺序当成单纯的分数排序。

变化可追踪，历史有依据

报告保留技能、自评和分析版本；确认计划时重新核对输入。更新自评或完成任务不会自动改写旧报告，学习后的能力变化需要本人重新确认。

05 / 技术栈

每一层技术，都有具体职责。

从各项技术的具体用法，到它们如何配合完成一次操作。

交互界面
  • Vue 3
  • TypeScript
  • Vite
  • Pinia

将工作台、自评和规划连接成连续交互，管理会话与页面状态。

  • Vue 3 与 TypeScript

    Vue 组件承载方向选择、自评表单和计划预览，响应式状态驱动加载、错误与确认步骤。TypeScript 描述技能、报告等数据结构，让组件传值和接口处理在开发阶段有可检查的约束。

  • Pinia

    集中管理登录用户、会话恢复和退出状态，使不同页面使用同一份身份上下文。会话恢复失败时保留明确反馈，身份变化后检查请求所属会话，减少旧响应重新写入界面的风险。

  • Vite

    配合 Vue 插件组织开发服务与前端构建，开发时将 API 请求转发到后端。构建脚本先执行类型检查再生成页面资源，把开发工具职责与实际评分、排期逻辑分开。

如何配合

保存自评后由接口返回结果；进入规划页时读取报告，再依次完成预览与明确确认，页面不会直接写数据库。

统计可视化
  • ECharts

将固定范围内的技能频率与类别转成图表，配合文字解释比较依据。

  • ECharts

    条形图展示岗位中各技能的出现频率，环形图展示技能类别的出现次数分布。组件使用 SVG 渲染并响应容器尺寸变化，点击条形可选择技能，同时保留文字明细和分母说明，便于核对图中数值。

如何配合

图表读取接口提供的统计结果；选择技能只改变当前高亮，不重算样本范围，也不把频率解释为录用概率。

业务接口
  • Python
  • FastAPI
  • Pydantic

校验输入，衔接差距评估、计划预览与明确确认，保持页面和业务规则一致。

  • Python 与 FastAPI

    Python 实现差距评分、前置关系展开和时间排期，FastAPI 将这些服务组织为可请求的接口。路由层接入身份与权限检查，预览和确认分别处理，使浏览结果与实际保存成为两个明确动作。

  • Pydantic

    将自评等级、说明长度、版本号和确认参数定义为输入模型，在进入业务逻辑前校验类型与范围。例如自评等级限定为零至三级；计划确认还会重新核对输入版本，不能仅依赖前端按钮状态。

如何配合

确认计划时重新读取当前档案和报告，核对预览输入，再调用数据库层保存计划、任务及依赖关系。

数据与版本
  • MySQL
  • SQLAlchemy
  • Alembic

保存技能档案、分析范围、历史报告与任务依赖，使结果能回到对应版本。

  • MySQL 与 SQLAlchemy

    MySQL 保存业务记录及其关联，SQLAlchemy 用表定义和查询表达式组织读写。报告保存生成时的输入快照；确认计划时在同一事务内写入计划、任务和依赖，便于保持这组关联记录一致。

  • Alembic

    通过带版本的迁移脚本维护表、字段和约束，让数据库结构变化有明确的执行顺序。结构演进集中记录在迁移目录，便于核对某项业务功能依赖的字段，以及应用所预期的数据库版本。

如何配合

用户后续更新自评时增加档案版本；已生成报告仍保留原输入，读取历史结果无需用最新档案反向重算。

批量分析
  • Apache Spark
  • PySpark
  • FP-Growth

通过后台任务汇总岗位技能统计与共现规则，再发布为前端可读取的分析结果。

  • Apache Spark 与 PySpark

    PySpark 用 Python 编写 Spark 数据处理任务，对固定的岗位快照展开技能并按城市、技能分组计数。任务保存有效样本、排除原因与聚合结果，由后台依次执行，页面读取发布结果时无需重新运行整批统计。

  • FP-Growth

    从有效岗位的技能集合中提取频繁项集与关联规则，再按支持度、置信度等条件筛选。它用于提示哪些技能经常共同出现；共现关系不等于学习先后，学习计划仍使用人工维护的前置关系。

如何配合

后台先保存技能统计，再计算共现规则并发布；业务接口读取这份固定范围的结果，供图表和差距评估使用。

06 / 项目思考

实现过程中的选择与思考。

解释范围，而不推断录用结果

覆盖度只比较固定样本中的技能与自评，不是能力认证或录用概率。共现规则用于配套技能提示，不能代替人工前置关系；本页图像和视频均为合成演示。

明确规则，也保留适用边界

词典提取依赖技能规则的维护，排期依赖预设学习时长。每份计划单独核算预算，不会自动扣除其他计划占用的时间；实际投入与学习效果仍需持续复盘。
