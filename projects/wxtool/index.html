03 / 桌面工具 · 二次开发

微语 / WXtool

一项基于 WechatVibe 二次开发的 Windows 桌面应用实践，将会话统计、原文回看与可选分析组织在同一工作台中。

基于 WechatVibe 二次开发

项目简介问题与思路操作演示界面与功能实现原理技术栈项目思考

01 / 项目简介

从聊天回顾出发，连接桌面交互与数据分析。

这项实践从回看聊天时的两个需求展开：快速了解一段交流的规模与节奏，以及找到具体消息并读到上下文。连续的聊天气泡不便于概览，单条搜索结果又容易失去语境，因此工作台把消息统计与原文入口放在一起。

项目基于 WechatVibe 二次开发，在上游聊天读取与分析能力之上整理会话概览和快捷入口。这里重点展示桌面界面、本机服务与分析任务如何衔接，以及如何区分可核对的统计和需要审慎理解的模型判断。

应用场景

Windows 上的个人聊天回顾场景：浏览有权访问的会话、查找原文、了解已加载消息的交流节奏。

实践内容

  • 会话概览与消息统计
  • 关键词搜索与原文定位
  • 分析任务状态与账号隔离

02 / 问题与思路

从具体问题，梳理实现思路。

01

记录很多，缺少概览

遇到的问题
只看连续的聊天气泡，很难快速了解这一段交流的规模和节奏。
实现思路
以已加载消息为明确范围，汇总数量、类型、平均文本长度、发言占比和小时分布，形成会话概览。
02

找到一句话，仍缺上下文

遇到的问题
搜到关键词后，孤立的句子可能不足以理解当时讨论的事情。
实现思路
把关键词或日期搜索与原文定位连接起来，搜索结果可以继续展开前后消息。
03

统计与推测容易混在一起

遇到的问题
消息数量与情绪、意图等模型判断性质不同，需要分别理解。
实现思路
让工作台统计独立于模型运行，分析另设入口，并用进度与待分析状态说明当前任务情况。

04 / 实现原理

一次操作，背后如何流转。

先限定样本，再解释数字

统计只处理已加载消息。未知发送者单独计数，无效时间不进入时段图；群聊将其他成员合并显示，避免把局部样本包装成完整关系结论。

桌面交互与分析分工

Electron 承载界面，Python 处理本机数据和任务，Node 负责模型调用。界面通过本机 HTTP 读取状态，模型计算不直接塞进页面交互代码。

切换账号也切换上下文

SQLite 文件按账号区分，历史游标校验账号与会话；前端在账号变化时取消旧请求并重置当前视图，减少旧结果串入新会话的风险。

05 / 技术栈

每一层技术，都有具体职责。

桌面容器
  • Electron

承载 Windows 窗口与受限桌面接口，将本机服务页面组织为桌面应用。

沟通工作台
  • HTML
  • CSS
  • JavaScript

实现会话选择、统计计算、历史搜索与消息展示，并同步账号切换和任务状态。

本机服务
  • Python
  • HTTP

组织消息读取与账号校验，通过本机接口衔接历史查询和分析任务。

分析执行
  • Node.js
  • TypeScript
  • ONNX Runtime

将模型调用与页面交互分开，执行本地 Laya 或通过连接器调用所配置的 API。

本地持久化
  • SQLite

保存会话选择、分析结果与进度，并区分账号和分析来源。

06 / 项目思考

实现过程中的选择与思考。

本地能力与 API 各有边界

这项实践需要说明不同分析路径的数据去向：事实统计和本地 Laya 可在本机处理，远程 API 分析与聊天助手则会发送相关上下文给所配置的服务。整个工具不能概括为全程离线，模型推测也不能替代对原文的判断。

展示操作，不替代真实验收

图片与视频使用合成聊天，视频未连接模型。这些材料用于说明工作台、搜索和统计的实现，分析准确度与不同微信版本的兼容性仍需在相应环境中验证。
